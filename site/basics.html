Network basics

Three ideas carry most of networking: things have addresses, data travels in pieces, and each piece is handled in layers.

1. A network is a delivery agreement

Two computers are on the same network when they can exchange data without a human carrying it.

More detail

That requires three things to be agreed on: how to find each other (addressing), how to hand data over (a link), and how to recover when something is lost (the protocol).

Address vs. name. Humans use names such as example.com; networks route to addresses such as 203.0.113.9. DNS is the translator, and it is the first thing that happens when you open a page.

2. Data travels in packets

A message is cut into packets, and each packet carries its own addressing.

More detail

Each packet carries a header with where it came from, where it is going, and its place in the sequence. Packets can arrive out of order, by different routes, or not at all; the protocol above decides what to do about that.

3. The OSI model, without the ceremony

Seven names, one purpose: to say which problem is being solved right now. Click a layer.

Application

The protocols your software speaks: HTTP for pages, SMTP for mail, DNS for names.

Fails as: a 404, a certificate warning, wrong credentials. The network is fine; the conversation is not.

Presentation

Turns bytes into something both ends understand: UTF-8, JPEG, TLS record framing, compression.

Fails as: garbled characters, an image that renders as noise, a decryption error.

Session

Keeps track of a conversation: start it, keep it alive, end it. Cookies and TLS sessions live near here.

Fails as: being logged out on every request, or a connection that times out mid-transfer.

Transport

TCP numbers the pieces and re-sends what is lost; UDP just sends. Ports decide which program on the host receives the data.

Fails as: a page that loads halfway, or a "connection refused" when nothing listens on that port.

Network

IP addresses and routing. This layer answers one question: which interface does this packet leave by, to get closer to the destination?

Fails as: "destination host unreachable", or a ping that works while the web page does not.

Data link

Moves a frame to the next device on the same link, using MAC addresses, switches and Wi-Fi frames.

Fails as: a switch loop, duplicate frames, or a device that is plugged in but never appears.

Physical

Voltage, radio, light. The part that is genuinely a cable problem.

Fails as: no link light at all, or intermittent drops when someone bumps the connector.

Layers in practice

The internet does not really use seven strict layers. It uses four: link, internet, transport and application. The OSI names survive because they are a useful vocabulary for arguing about where a fault is.

Problem you seeLayer worth checking first
Nothing works, no link lightPhysical
Only one machine affectedData link / IP configuration
Ping works, browsing failsTransport or application (ports, DNS)
Works on Wi-Fi, not on cableData link, then routing
